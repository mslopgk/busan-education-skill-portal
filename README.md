### 기존 그림 교체 (작성자 승인)
`tools/swap_figures.py` 가 `[그림 N]` 캡션 문단에서 거슬러 올라가 바로 앞 그림 문단의 blip →

가로세로비로 다시 계산한다. **캡션 텍스트와 본문은 건드리지 않는다.**

| 문서 | 교체 |

| A안 | 그림 6 → `A-main-crop` · 그림 7 → `A-detail` · 그림 8 → `A-admin` |
| B안 | 그림 6 → `B-main-crop` · 그림 7 → `B-detail` · 그림 8 → `B-admin` |

통합비교본은 같은 화면을 그림 3·5·7 로 재사용하므로 함께 맞췄다 — 나란히 제출될 때 개별
제안서는 새 캡처, 비교본은 옛 캡처가 되면 안 된다.

메인 화면은 하단 공지사항·푸터를 잘라(`*-crop`) 비율을 1.15 로 낮췄다. 캡션이 검색·필터·목록을
말하는데 공지·푸터는 무관하고, 자르지 않으면 20cm 높이가 되어 한 쪽을 통째로 쓴다.

교체 후에는 **그 화면을 대신하려고 넣었던 사진 슬롯을 다시 제거**했다. 업그레이드된 그림 바로
앞에 붙어 앞 페이지를 비웠기 때문이다.

폭은 `min(15.5cm, 20cm ÷ 가로세로비)`. A안 그림 7(상세)만 원본이 세로 4386px 이라 11.7cm 로
좁아지는데, 캡션이 "목적·절차·예시·유의사항을 한 화면에서" 라고 말하므로 잘라낼 수 없다.

원본 4종은 그대로 두고 `_보강.docx` 를 따로 만들었다. 같은 이름의 `.pdf` 는 실제 Microsoft Word 로 출력한 검수용이다.

## 원문 무수정 보증

`tools/docx_augment.py` 는 `word/document.xml` 에 새 `<w:p>`·`<w:tbl>` 만 끼워 넣는다. 기존 run 은 건드리지 않는다.

검증 결과 — 4종 모두 **원문 전체 문자열이 순서까지 보존된 부분수열**로 존재:

```
A안  13,955 → 16,609자   B안  14,694 → 17,976자
C안  17,080 → 21,391자   통합  5,414 →  7,406자
```

Word COM 으로 열어 리페어 프롬프트 없이 PDF 출력되는 것까지 확인했다.
백지 페이지는 4종 모두 p2 하나뿐이고, 이는 원본에도 있는 목차 뒤 여백이다.

### 페이지 넘김 처리
검수에서 표가 쪽을 넘어가면 다음 장에 머리글이 없고, 캡션만 앞 장에 남는 문제가 나왔다. 삽입기가 처리한다.

- 신규 표 머리글 행에 `<w:tblHeader/>` — 다음 쪽에서 머리글 반복
- 모든 신규 행에 `<w:cantSplit/>` — 행이 셀 중간에서 쪼개지지 않음
- 표 제목 문단에 `keepNext`, 이미지 문단에 `keepNext` — 캡션 고아 방지
- 원본이 쓰는 `<w:br w:type="page"/>` 단독 문단이 밀려나 백지 쪽을 만들던 현상까지 감지해 붙여 둔다

### 번호 체계
기존 `[그림 N]` 번호를 다시 매기는 것도 '내용 수정'이므로, 신규 이미지는 **별도 계열**을 쓴다.

- `[그림 N]` — 기존. 손대지 않음
- `[사진 N]` — 신규 실사진
- `[화면 N]` — 신규 UI 화면 캡처
- `[표 A-1]` … — 신규 표 (기존 표에는 번호가 없어 충돌하지 않음)

번호는 문서 내 실제 등장 순서로 매긴다(앵커 문단 위치 기준 정렬).

## 도구

| 파일 | 역할 |
|---|---|
| `tools/docx_augment.py` | docx 에 표·이미지 삽입. `augment(src, dst, ops)` / `verify(src, dst)` |
| `tools/build_ops.py` | placement + tables + photos + 화면을 합쳐 ops 생성 후 삽입 |
| `tools/render.py` | HTML → PNG (헤드리스 Chrome, **1280 CSS px @2배**) |
| `tools/patch_screens.py` | Stitch 가 반영하지 못한 수정을 HTML 에 직접 적용 |
| `tools/preview.py` | 보강본 → Word COM → PDF → 페이지 PNG |

### 렌더링 시 주의 두 가지
1. **폭은 반드시 1280 CSS px + 배율 2배.** 페이지들이 콘텐츠를 `max-w-[1280px]` 로 가운데 정렬하므로
   창을 2560 CSS px 로 열면 콘텐츠가 화면 절반만 차지하고 좌우에 거대한 여백이 생긴다.
2. **창 높이를 크게 잡지 말 것.** 다수 페이지가 `min-h-screen` 을 써서 창이 크면 레이아웃이 늘어나
   푸터가 맨 아래로 밀리고 가운데가 텅 빈다. `render.py` 의 `HEIGHT` 표(CSS px)를 쓴다.
